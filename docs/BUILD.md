# Building and running

## Requirements

- Node 20+ and npm. Expo SDK 57 (React Native 0.86, New Architecture, React 19.2).
- For device builds: an Expo account and `eas-cli` (`npx eas-cli@latest ...`). No local Xcode/Android Studio needed when building in the cloud.
- Python 3 + Pillow only if you want to regenerate the icon/audio assets.

## Ways to run

| Where | Command | Ads | Notes |
|---|---|---|---|
| Browser | `npm run web` | none | Fastest way to play and design rooms. Keyboard: arrows/WASD, Space = wait, Z = undo, R = restart, Esc = pause. |
| Expo Go | `npx expo start` | simulator | AdMob, UMP and ATT are native modules Expo Go does not contain, so the game falls back to the labelled simulator. |
| Development build | `eas build --profile development` then `npx expo start --dev-client` | AdMob **test** units | The right way to test consent and real SDK callbacks. |
| Preview (internal) | `eas build --profile preview` | AdMob test units | Release-mode build; `ORL_ADMOB_ALLOW_TEST_UNITS=1` keeps test ads on. Android produces an installable APK. |
| Production | `eas build --profile production` | your real units | Without real unit IDs a release build shows **no ads** (never test ads, never the simulator). |

The ad simulator can only ever appear when `__DEV__` is true. See `src/services/ads/providerFactory.ts`.

## Environment variables

Set these in EAS (`eas env:create`, or the project's Environment variables page). None are secrets, but none are committed either.

| Variable | Purpose | Default |
|---|---|---|
| `ORL_IOS_BUNDLE_ID` | iOS bundle identifier | `com.example.oneroomleft` (placeholder) |
| `ORL_ANDROID_PACKAGE` | Android application id | `com.example.oneroomleft` (placeholder) |
| `ORL_ADMOB_IOS_APP_ID` | AdMob iOS app id (`ca-app-pub-…~…`) | Google test app id |
| `ORL_ADMOB_ANDROID_APP_ID` | AdMob Android app id | Google test app id |
| `ORL_ADMOB_IOS_REWARDED`, `ORL_ADMOB_IOS_INTERSTITIAL` | iOS ad unit ids (`ca-app-pub-…/…`) | empty → test units in dev, no ads in release |
| `ORL_ADMOB_ANDROID_REWARDED`, `ORL_ADMOB_ANDROID_INTERSTITIAL` | Android ad unit ids | as above |
| `ORL_ADS_MODE` | `admob`, `mock` (dev only) or `off` | `admob` |
| `ORL_ADMOB_ALLOW_TEST_UNITS` | `1` lets a release build use Google test units | unset |
| `EAS_PROJECT_ID` | written by `eas init` | unset |

The `com.example.*` identifiers are placeholders and must be replaced before any store upload: bundle ids cannot be changed after the first release.

## First-time EAS setup

```bash
npx eas-cli@latest login
npx eas-cli@latest init                 # creates the EAS project; set EAS_PROJECT_ID from its output
npx eas-cli@latest env:create --name ORL_IOS_BUNDLE_ID --value com.yourcompany.oneroomleft --environment production
# ...repeat for the other variables and for the preview/development environments
npx eas-cli@latest build --profile development --platform ios
```

Credentials (signing certificates, keystores, provisioning profiles) are managed by EAS. Do not commit `.jks`, `.p8`, `.p12` or `.mobileprovision` files; `.gitignore` already excludes them.

## Versioning

`version` in `app.config.ts` is the user-facing version shown in Settings. Build numbers use EAS remote versioning (`appVersionSource: remote`, `autoIncrement` on production).

## Native folders

`ios/` and `android/` are generated by prebuild (Continuous Native Generation) and ignored. Configure native behaviour through `app.config.ts` and config plugins only.
